# A closed Rocq proof that the BB(6) holdout halts

`proof/Final.v` proves, in Rocq's kernel, with no extracted code:

```coq
Theorem bb6_holdout_halts : halts tm c0.
```

for `tm = 1RB0LF_1RC1RA_0RD0RB_1LE---_0LA1LE_1RD1LA` from the blank tape. `tm`, `c0` and `halts` are the definitions in `base/` (unchanged copies of the busycoq and `rocq/bb6` theories), the same as in `base/theories/Statement.v`. The theorem has no step count; the exact-count theorem is separate work.

## Build

Needs Rocq 8.20.1 with native compilation, on OCaml 4.14 with flambda, plus a C toolchain and GMP:

```
opam switch create rocq-fl --packages=ocaml-variants.4.14.2+options,ocaml-option-flambda
eval $(opam env --switch=rocq-fl)
opam install coq.8.20.1 coq-native
./run_all.sh            # one job per core; run_all.sh N for N parallel jobs
```

Without flambda it still works, about 2x slower. `run_all.sh` needs `ulimit -s unlimited` and sets it itself. Finished jobs are kept as `.vo` files, so it can be restarted.

**Status: done and checked.** All 313 jobs passed in the kernel on a 128-core c7a.32xlarge: 275 core-hours, 2 h 40 min wall. Job times: 12 to 117 min, median 57 min. Peak memory 1.55 GB per job. `Final.v` itself takes 1.5 s. Build of `theories/`: about 5 min on 8 cores.

On an 8-core desktop: about 34 hours and 13 GB in total, scaled from that run (not measured on a desktop). Per-job times and memory (`run_out/log/times.txt`), `Final.out` and hashes of the `.vo` files are in `run_out/`.

`run_all.sh` alone, from a clean checkout with the switch active, is the whole procedure: it builds `theories/`, runs every job and writes `proof/Final.vo` and `proof/Final.out`. No `.vo` file needs copying. Expected hashes are in `run_out/vo.sha256`.

How far that has been tested: the 312 orbit jobs ran with the same `coqc` command but through a separate job script on the run box. `run_all.sh` itself, from clean, built `theories/`, ran the halt job and compiled `Final.v`, with the orbit jobs' `.vo` files taken from the run (their hashes are in `run_out/vo.sha256`); `HTop.vo`, `Cuts.vo`, `JHalt.vo` and `Final.vo` came out byte-identical. A full from-source run with `run_all.sh` alone, on a separate machine, then passed all 313 jobs and gave a byte-identical `Final.vo` (`run_out/verify_rebuild.log`, `run_out/verify_Final.out`).

## Layout

- `theories/`: the checker and its soundness. `HLines` region lines and their pull-back margin. `HCore`, `HAbs`: the meaning of a block lemma, stops, composition. `HBand`: the table and the recursion below the band (`bn_sound`). `HTop`: exact recursion above the band, stops, applying a block (`try_block_sound`), the run theorems (`run_seg_sound`, `run_halt_at_sound`).
- `proof/`: generated by `gen/gen_final.py` from the cut points in `rocq/bb6/cert/chunks.tsv`. `Cuts.v` holds the cut points, `Jnnnn.v` one job each, `JHalt.v` the halting stretch, `Final.v` the chain.
- `base/`: unchanged copies of the theories this builds on.

## What is trusted

`Print Assumptions bb6_holdout_halts` (in `proof/Final.out`) lists 41 items, all from Rocq's standard library: `PrimInt63.*` (16, the primitive integers), `Uint63.*` (13, their specifications), `PArray.*` (12, primitive arrays and their specifications). Nothing else.

Beyond that:

- The jobs run under `native_compute`, so `ocamlopt` is trusted along with the Rocq kernel. There is no extraction and no separately written checker: a job is a kernel conversion check of `run_seg ... = true`.
- The stricter option is the kernel VM, which does not use `ocamlopt`: compile the job files with `-native-compiler no` and the same proofs check under the VM. Measured on one 16-chunk window it is about 6x slower (238 s vs 40 s), so about 1,500 core-hours (extrapolated from that window; not run in full).
- `coqchk` was not run.
- Soundness does not depend on the cut points, the table contents or the fixed-point numbers. These only choose what to try: a wrong cut point makes a job fail. Region tests are exact integer inequalities; the fixed-point point is checked against them.
